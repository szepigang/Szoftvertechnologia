1. Bevezetés

Jelen dokumentum a Szoftvertechnológia projekt H5 (Transition) mérföldkövének eredményeit foglalja össze. A H4 mérföldkőben elkészített Analízis modell és Rendszertervezési dokumentáció alapján ebben a fázisban elvégeztük a részletes objektumtervezést, kialakítottuk a C# / ASP.NET Core alapú alkalmazás rétegzett modulstruktúráját és fordítható kódvázát (skeleton), valamint összeállítottuk a kritikus üzleti folyamatokat ellenőrző tesztelési tervet.

2. Objektumtervezési tevékenységek

2.1. A rendszer vezérlésének kidolgozása

A rendszer vezérlése két egymást kiegészítő mechanizmusra épül: a felhasználói kérésekre reagáló eseményvezérelt HTTP API vezérlőkre, valamint az időzített háttérfolyamatokra (BackgroundService).

  • Kérés-vezérelt folyamatok (Controllers → Services): A webes felületekről érkező kéréseket (szobakeresés, foglalás indítása, fizetési webhook, takarítási állapot frissítése) a vékony REST kontrollerek (FoglalasController, TakaritasController, AdminController) fogadják, majd továbbítják az üzleti logikát koordináló szolgáltatásosztályoknak (FoglalasService, TakaritasService).
  • Aszinkron háttérfolyamatok:
    • IcalSyncBackgroundService: 5 percenként lefutó időzített szolgáltatás, amely lekérdezi a külső Booking.com és Airbnb naptárakat, frissíti a központi naptárat, és ütközés esetén riasztást hoz létre.
    • ZarolasTakaritoService: 1 percenként ellenőrzi a foglalasi_zarolas táblát, és felszabadítja azokat az ideiglenes zárolásokat, amelyeknél a fizetési időablak (15 perc) sikertelenül lejárt.
  • Láthatóság és függőségkezelés: Az üzleti szolgáltatások nem közvetlenül az adatbázis-osztályokat példányosítják, hanem interfészeken (IFoglalasRepository, IPaymentGateway, IEmailSender) keresztül kommunikálnak, amelyeket az ASP.NET Core beépített Dependency Injection (DI) konténere biztosít.

2.2. Osztályok közötti kapcsolatok implementációja

Az analízismodellben meghatározott asszociációkat és számosságokat az alábbi objektumorientált és Entity Framework Core megoldásokkal valósítjuk meg:

Kapcsolat (Analízis modell) Számosság Implementációs mód (C# / EF Core)
Vendégház – Szoba 1 : 1..* A Szoba osztályban kötelező int VendeghazId idegen kulcs és Vendeghaz navigációs tulajdonság; a Vendeghaz osztályban ICollection<Szoba> Szobak gyűjtemény.
Szoba – Foglalás 1 : 0..* A Foglalas osztályban int SzobaId és Szoba referencia; a Szoba osztályban ICollection<Foglalas> lista.
Foglalás – Kupon 0..* : 0..1 Opcionális (nullable) idegen kulcs (int? KuponId) a Foglalas osztályban, mivel kupon megadása nélkül is lehet foglalni.
Foglalás – Fizetés 1 : 0..1 Egy-az-egyhez (opcionális) kapcsolat a Fizetes táblában lévő egyedi (UNIQUE) int FoglalasId idegen kulccsal.
Foglalási ütközés – Foglalás 0..* : 2..* A több-a-többhöz kapcsolatot a köztes UtkozesFoglalas kapcsolóosztály és kompozit kulcs oldja fel.
Takarítási feladat – Takarítási fotó 1 : 0..1 A TakaritasiFoto osztályban tárolt int FeladatId egyedi idegen kulcs, amely a képfájl elérési útvonalát köti a feladathoz.
Külső szolgáltatók (Fizetés, SMTP) Függőség Interfész alapú csatolás (IPaymentGateway, IEmailSender), így a külső API-k teszteléskor könnyen helyettesíthetők mock objektumokkal.

2.3. Modulokba és csomagokba (namespace) szervezés

A tiszta rétegzett architektúra (Clean Architecture elvek) érdekében a forráskódot négy fő modulba és névtérbe szerveztük:

VendeghazApp.Domain

Tartalmazza az üzleti entitásokat (Szoba, Foglalas, Kupon, TakaritasiFeladat), a felsorolási típusokat (FoglalasStatusz, SzobaAllapot) és az alapvető üzleti validációkat.

VendeghazApp.Application

Tartalmazza az alkalmazás-szolgáltatásokat (FoglalasService, NaptarSyncService, TakaritasService), a DTO adatátviteli objektumokat és a repository/külső API interfészeket.

VendeghazApp.Infrastructure

Tartalmazza az EF Core ApplicationDbContext osztályt, a PostgreSQL migrációkat, a Repository implementációkat, valamint a Stripe/Barion, SMTP és iCal klienseket.

VendeghazApp.Web

Tartalmazza a REST API kontrollereket, a hitelesítési és RBAC jogosultsági beállításokat, a háttérfolyamatok regisztrációját és a reszponzív kliensoldali felületet.

3.3. Foglaláskezelő szolgáltatás és ütközésvédelem

namespace VendeghazApp.Application.Services;

public class FoglalasService
{
    private readonly IFoglalasRepository _foglalasRepo;
    private readonly INaptarRepository _naptarRepo;
    private readonly IPaymentGateway _paymentGateway;
    private readonly IEmailSender _emailSender;

    public FoglalasService(
        IFoglalasRepository foglalasRepo,
        INaptarRepository naptarRepo,
        IPaymentGateway paymentGateway,
        IEmailSender emailSender)
    {
        _foglalasRepo = foglalasRepo;
        _naptarRepo = naptarRepo;
        _paymentGateway = paymentGateway;
        _emailSender = emailSender;
    }

    public async Task<string> FoglalasKezdemenyezeseAsync(FoglalasLetrehozasDto dto)
    {
        if (dto.Erkezes >= dto.Tavozas)
            throw new ArgumentException("A távozás dátumának későbbinek kell lennie az érkezésnél.");

        // 1. Atomi elérhetőség-ellenőrzés és 15 perces ideiglenes zárolás létrehozása
        bool zarolva = await _naptarRepo.TryIdoszakZarolasaAsync(
            dto.SzobaId, dto.Erkezes, dto.Tavozas, TimeSpan.FromMinutes(15));

        if (!zarolva)
            throw new InvalidOperationException("A kiválasztott szoba időközben foglalttá vált.");

        // 2. Árkalkuláció (opcionális kuponkedvezménnyel) és foglalás mentése FizetesreVar státusszal
        var foglalas = await _foglalasRepo.CreatePendingFoglalasAsync(dto);

        // 3. Külső fizetési munkamenet indítása
        return await _paymentGateway.CreateCheckoutSessionAsync(foglalas.FoglalasId, foglalas.Vegosszeg);
    }

    public async Task FizetesVisszaigazolasaAsync(int foglalasId, string tranzakcioId, bool sikeres)
    {
        if (!sikeres)
        {
            await _naptarRepo.ZarolasFeloldasaAsync(foglalasId);
            return;
        }

        var foglalas = await _foglalasRepo.VeglegesitAsync(foglalasId, tranzakcioId);
        await _naptarRepo.ZarolasVeglegesiteseAsync(foglalasId);
        await _emailSender.SendVisszaigazolasAsync(foglalas);
    }
}

3.4. Ütemezett iCal szinkronizáló háttérfolyamat

namespace VendeghazApp.Web.BackgroundJobs;

public class IcalSyncBackgroundService : BackgroundService
{
    private readonly IServiceScopeFactory _scopeFactory;

    public IcalSyncBackgroundService(IServiceScopeFactory scopeFactory)
    {
        _scopeFactory = scopeFactory;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            using var scope = _scopeFactory.CreateScope();
            var syncService = scope.ServiceProvider.GetRequiredService<NaptarSyncService>();

            // Külső Booking.com és Airbnb naptárak lekérdezése és ütközésvizsgálat
            await syncService.SzinkronizalMindenKulsoNaptaratAsync(stoppingToken);

            await Task.Delay(TimeSpan.FromMinutes(5), stoppingToken);
        }
    }
}

4. Tesztelési terv

4.1. Tesztelési stratégia és eszközök

A tesztelés célja annak igazolása, hogy a rendszer üzletileg kritikus folyamatai (foglalási ütközések megelőzése, pénzügyi számítások, külső naptárszinkronizáció és offline takarítói adatrögzítés) hibamentesen működnek. A tesztelést három szinten végezzük:

  • Egységtesztek (Unit Tests – xUnit + Moq): Az üzleti logika izolált ellenőrzése (árkalkuláció, kuponérvényesség, dátumintervallumok átfedésvizsgálata).
  • Integrációs tesztek (WebApplicationFactory + PostgreSQL): A vezérlők, szolgáltatások és az EF Core adatbázis-tranzakciók együttes tesztelése valós adatbázis-megszorítások mellett.
  • Rendszer- és elfogadási tesztek (Swagger UI, böngészős mobilnézet): A három felhasználói felület teljes munkafolyamatainak végigjátszása a H3 Use Case specifikációk alapján.
